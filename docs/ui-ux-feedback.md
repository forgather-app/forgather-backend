# Forgather Admin UI/UX 피드백 리포트

## 분석 대상
- `/view/admin/spaces` — 스페이스 관리 페이지
- `/view/admin/hosts` — 호스트 관리 페이지

---

## 1. 잘 된 점 (Strengths)

### 시멘틱 구조
`header > nav`, `main`, `footer`, `table > thead > tbody` 등 HTML 시멘틱 태그를 올바르게 사용하고 있다. 페이지네이션 버튼에 `aria-label`이 적용되어 있어 스크린 리더 접근성의 기본은 갖춘 상태.

### 디자인 시스템 토큰
`common.css`에 CSS Custom Properties로 색상, 간격, 그림자, 타이포그래피를 체계적으로 정의해두었다. Monochrome 테마 일관성이 있고, 변수명이 직관적이다.

### 상태 표시 배지
PUBLIC/PRIVATE 배지가 `badge-success`(초록), `badge-danger`(빨강)로 시각적 구분이 명확하다. pill 형태 + uppercase + letter-spacing 조합은 스캔성(scannability)이 좋다.

### 모션 & 접근성 기본
`prefers-reduced-motion: reduce` 미디어 쿼리를 적용해 모션 민감 사용자를 배려하고 있다. toast 알림에 적절한 transition이 적용되어 있다.

### Tailwind + 커스텀 CSS 하이브리드
Tailwind로 레이아웃 기본을 잡고, JS 동적 생성 요소만 별도 CSS로 관리하는 전략은 유지보수 관점에서 합리적이다.

## 2. 개선이 필요한 점 (Issues)

### 🔴 Critical (즉시 개선 권장)

#### 2.1 터치 타겟 미달
**문제:** 모든 버튼이 WCAG 2.1 최소 터치 타겟(44×44px)에 미달한다.

| 요소 | 현재 크기 | 권장 크기 |
|------|----------|----------|
| Logout 버튼 | 80×37px | 80×**44px** |
| 필터 적용 버튼 | 100×36px | 100×**44px** |
| 검색 아이콘 버튼 | 28×28px | **44×44px** |
| 페이지네이션 버튼 | 36×36px | **44×44px** |

**영향:** 모바일에서 오탭(mis-tap) 빈도 증가. 특히 페이지네이션이 밀집되어 있어서 인접 버튼을 잘못 누를 확률이 높다.

**수정 방향:** `min-height: 2.75rem(44px)`, 검색 아이콘은 padding 영역으로 터치 영역 확보. 모바일 breakpoint에서는 이미 `min-width: 2.5rem`을 적용하고 있으나, height도 맞춰야 한다.

#### 2.2 테이블 행 클릭 어포던스 부재
**문제:** 스페이스 코드에 underline 링크 스타일이 있지만, 테이블 행의 `cursor: auto`로 되어 있어 클릭 가능하다는 시각적 힌트가 부족하다. `>` 화살표 아이콘이 너무 작아 의미가 전달되지 않는다.

**수정 방향:**
- 행 전체에 `cursor: pointer` + hover 시 배경색 변경 (`bg-gray-50`)
- 스페이스 코드 컬럼을 `font-mono`로, 클릭 시 시각 피드백(active state) 추가
- 또는 행 우측 끝에 chevron 아이콘을 명시적으로 배치

#### 2.3 모바일 테이블 가로 스크롤 시 컬럼 절삭
**문제:** 375px 뷰포트에서 "생성 시간", "수정 시간" 컬럼이 완전히 잘려 보이지 않는다. 가로 스크롤 힌트도 없다.

**수정 방향:**
- `overflow-x: auto` 래퍼 + 스크롤 인디케이터(그라데이션 페이드)
- 또는 모바일에서는 카드 레이아웃으로 전환 (`@media (max-width: 768px)`)
- 최소한 "수정 시간"은 모바일에서 숨기고 상세 모달에서 확인하도록

### 🟡 Important (우선순위 높음)

#### 2.4 언어 혼재 (Mixed Language)
**문제:** 한 페이지 안에서 한국어와 영어가 체계 없이 혼용되고 있다.

| 한국어 | 영어 |
|--------|------|
| 스페이스 관리 페이지 | Space Details (모달 제목) |
| 필터 적용 | Items per page |
| 작품 소개 등록 여부 | Total: 50개 |
| 호스트 관리 페이지 | Page 1 of 4 |
| 게스트 페이지로 이동 | PUBLIC / PRIVATE |
| 생성 시간 ▼ | Logout |

**영향:** 인지 부하 증가. 사용자가 언어 전환을 계속해야 해서 정보 스캔 속도가 느려진다.

**수정 방향:** 어드민 페이지의 주 사용자가 한국어 사용자라면 전체 한국어로 통일. "Items per page" → "페이지당 항목 수", "Space Details" → "스페이스 상세", "PUBLIC" → "공개" 등. 기술적 용어(ID, Code)는 영어 유지 가능하지만, UI 라벨은 하나의 언어로 통일하는 것이 Consistency 원칙에 부합한다.

#### 2.5 필터/검색 영역 정보 구조 혼란
**문제:** Spaces 페이지 상단 영역의 정보 구조가 분산되어 있다.

```
[필터 라디오버튼] [필터 적용 버튼] .............. [Items per page 드롭다운]
[Total: 50개] ................................ [검색 입력 + 초기화 버튼]
```

필터 적용과 검색이 별도 행에 분리되어 있고, "Items per page"가 필터 영역에 들어가 있어 논리적 그룹핑이 어색하다. 검색 초기화 버튼은 `width: 0, height: 0`으로 보이지 않는 상태.

**수정 방향:**
- 필터/검색을 하나의 toolbar로 통합
- "Items per page"는 테이블 하단 페이지네이션 옆으로 이동
- 구조 예시: `[필터 드롭다운] [검색 입력] [적용/초기화]` 한 줄 구성

#### 2.6 Hosts 페이지 빈약한 기능
**문제:** Hosts 페이지에 검색, 필터, 정렬 기능이 전혀 없다. 현재 데이터가 1건이라 문제가 안 보이지만, 호스트가 수백 명으로 늘어나면 관리 불가.

**수정 방향:**
- 호스트명 검색 기능 추가
- 스페이스 개수 기준 정렬
- 호스트 클릭 시 해당 호스트의 스페이스 목록으로 drill-down

#### 2.7 모달 다이얼로그 UX
**문제:**
- 모달 제목이 "Space Details"(영어)인데 내부 라벨은 전부 한국어
- "등록한 작품 소개"에 placeholder "작품 소개를 등록하지 않음"이 빈 상태 표현으로 부자연스럽다
- "게스트 페이지로 이동" 버튼이 모달 내 유일한 액션인데, 모달을 닫는 방법이 X 버튼 또는 백드롭 클릭뿐
- read-only 필드가 일반 input처럼 보여서 편집 가능한 것처럼 오해할 수 있다

**수정 방향:**
- 모달 제목 "스페이스 상세"로 통일
- 빈 상태: "등록된 작품 소개 없음" 텍스트를 muted 색상으로 표시 (input이 아닌 텍스트로)
- read-only 필드는 input 대신 plain text + label 조합으로. 배경색 구분(`bg-gray-50`)으로 편집 불가임을 시각적으로 명시
- "닫기" 버튼 추가 (footer 영역)

### 🟢 Minor (점진적 개선)

#### 2.8 테이블 열 너비 비균형
**문제:** "스페이스 이름" 컬럼에 `111111111📌11111111111111111111` 같은 긴 문자열이 들어오면 레이아웃이 깨진다. 반면 "ID" 컬럼은 2-3자리 숫자인데 과도한 공간을 차지한다.

**수정 방향:** `table-layout: fixed` + 컬럼별 `width` 지정. 긴 텍스트는 `text-overflow: ellipsis; overflow: hidden; white-space: nowrap` 처리 후 hover tooltip으로 전체 내용 표시.

#### 2.9 정렬 상태 피드백 미흡
**문제:** "생성 시간 ▼"에 정렬 방향 표시가 있지만 다른 컬럼은 정렬 가능 여부가 불명확하다. 정렬 가능한 컬럼인지, 현재 어떤 정렬이 적용 중인지 알 수 없다.

**수정 방향:** 정렬 가능 컬럼에 hover 시 정렬 아이콘 표시, 활성 정렬 컬럼은 아이콘 + 헤더 텍스트 강조, `cursor: pointer`를 적용.

#### 2.10 Empty State 디자인
**문제:** `empty-state` CSS는 정의되어 있지만, 아이콘이 텍스트 이모지(`font-size: 3rem`)에 의존하고 있어 시각적 완성도가 떨어진다.

**수정 방향:** SVG 일러스트레이션이나 Lucide 아이콘 사용. "스페이스를 찾을 수 없습니다" + 부가 설명 + CTA 버튼("필터 초기화") 형태의 3단 구조 권장.

#### 2.11 키보드 네비게이션
**문제:** 테이블 행이 `<tr>` 클릭으로 모달을 여는데, `tabindex`나 `role="button"` 없이 구현되어 키보드로는 접근 불가. 스페이스 코드 링크(`<a>` 태그가 아님)에 포커스가 가지 않는다.

**수정 방향:** 클릭 가능한 행에 `tabindex="0"` + `role="row"` + `onkeydown` Enter/Space 핸들링 추가. 또는 스페이스 코드를 실제 `<a>` 태그로 변경.

#### 2.12 로딩 상태 개선
**문제:** "Loading..." 텍스트만 존재하고 스켈레톤 UI가 없다. 초기 로딩 시 빈 테이블 → 텍스트 → 데이터 로딩의 레이아웃 시프트(CLS)가 발생할 수 있다.

**수정 방향:** 테이블 행 형태의 스켈레톤 로딩 (`animate-pulse` + 회색 박스) 적용. 데이터 건수와 유사한 행 수의 스켈레톤을 미리 표시해 CLS 최소화.

## 3. 아키텍처 관점 코멘트

### CSS 파일 구조
현재 `common.css`(공통) + `spaces.css`(페이지별)로 분리한 것은 적절하다. 다만 Hosts 페이지에는 별도 CSS가 없어서, 향후 호스트 전용 스타일이 필요할 때를 대비해 `hosts.css` 분리를 미리 고려할 것.

### Tailwind + Vanilla CSS 경계
주석에 "Phase 6/7 마이그레이션"이 언급되어 있는데, JS 동적 생성 요소의 스타일을 CSS 파일에 유지하는 현재 전략은 합리적이다. 다만 Tailwind 클래스와 커스텀 CSS가 동일 요소에 적용될 때 specificity 충돌 가능성이 있으므로, `@layer`를 활용해 우선순위를 명시적으로 관리하는 것을 권장한다.

### SSR(Thymeleaf) + CSR(JS) 혼합
서버에서 HTML을 렌더링하고, JS에서 데이터를 fetch해 테이블을 동적으로 그리는 구조로 보인다. 이 경우 SEO는 어드민이라 무관하지만, 초기 로딩 시 빈 테이블이 보이는 Flash of Empty Content 문제가 있다. Thymeleaf에서 초기 데이터를 서버사이드 렌더링하고, 이후 페이지네이션/필터만 JS로 처리하는 방식이 UX 관점에서 더 매끄럽다.
